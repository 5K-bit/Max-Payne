MaxPayne is a local developer-environment doctor. It runs health checks for Python, Git, Docker, Ollama, local ports and configured OBEOS service endpoints, keeps a SQLite history of scans, writes structured JSON reports, and offers remediation that is dry-run by default and approval-gated.

**Pre-release.** Suitable for diagnosing a development workstation, not for unattended production use.

### What it does

- Diagnostic profiles: `all`, `minimal`, `workstation`, `obeos` (`maxpayne profiles`).
- `maxpayne diagnose`, `doctor <group>`, `ports`, `report -o file.json`, `history`, `explain`.
- Remediation (`maxpayne remediate <id>`): dry-run by default; `--apply --approve` for mutating fixes; destructive fixes also need `--allow-destructive`.
- Optional dashboard and JSON API (`pip install "maxpayne[web]"`, then `maxpayne serve`, bound to 127.0.0.1).
- `maxpayne --version` for installed-version checks.

### Verified for this release

- 31 automated tests pass; CI runs on Python 3.11 and 3.12 (Linux). The `main` CI failure (missing FastAPI test dependencies in the `dev` extra) is fixed.
- Wheel and sdist build, `twine check` passes, and the wheel installs and runs in a clean virtual environment.
- Live run on a Linux machine (Python 3.13): every profile, scan history, JSON report, the dashboard routes, live and dead service probes (URL credentials stripped from reports) and the approval gates were exercised. Missing tools (Ollama) are reported as failures with a message, not hidden.
- Transcript: `docs/evidence/maxpayne-live.txt`.

### Known limitations

- Windows checks are covered by unit tests with sample data. They are skipped on Linux and were not run on a live Windows host for this release.
- The apply path for mutating remediations is covered by unit tests; it was not applied to a real machine during acceptance. The destructive path was only verified to be blocked.
- The dashboard has no authentication; keep it on localhost.
- No long-running soak test, and no history retention policy: the SQLite file grows with every scan.
- Docker checks report the daemon state at scan time; they do not manage containers.

Checksums are in `SHA256SUMS`. Install and first-use steps: `docs/runbook.md`. Changes: `CHANGELOG.md`.
